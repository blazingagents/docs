# Blazing Agents

Blazing Agents runs the production infrastructure for your AI agents, so you can ship agent features without building a backend for them.

You write the agent logic: instructions, the model it uses, and the tools it can call. Blazing Agents runs everything around it. Conversations are stored, Plus workspaces keep their files between sessions, background tasks keep running after your request returns, and every turn's token usage is tracked. You call it from your backend with an SDK or plain HTTP. Read [why teams use Blazing Agents](/why) for the longer case.

## See it work [#see-it-work]

A typical integration is one chat route on your backend. Your frontend posts the user's message to it, and the route streams the agent's reply back. Set `BLAZING_AGENTS_API_KEY` from your [dashboard](https://www.blazingagents.com/app/keys) and `OPENROUTER_API_KEY` from OpenRouter.

### Run once: save the provider [#save-the-provider]

Save the model provider your agents use. Run this script once and keep the printed provider ID. Provider names must be unique.

```typescript tab="TypeScript"
import { BlazingAgents } from "@blazingagents/sdk";

const client = new BlazingAgents({
  apiKey: process.env.BLAZING_AGENTS_API_KEY!,
});

const provider = await client.providers.create({
  name: "OpenRouter",
  providerType: "openrouter",
  baseUrl: null,
  apiKey: process.env.OPENROUTER_API_KEY!,
});

console.log(`BLAZING_AGENTS_PROVIDER_ID=${provider.id}`);
```

```python tab="Python"
import os

from blazing_agents import BlazingAgents

with BlazingAgents() as client:
    provider = client.providers.create(
        name="OpenRouter",
        provider_type="openrouter",
        api_key=os.environ["OPENROUTER_API_KEY"],
    )
    print(f"BLAZING_AGENTS_PROVIDER_ID={provider.id}")
```

```rust tab="Rust"
use blazing_agents::providers::ProviderType;
use blazing_agents::Client;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = Client::from_env()?;

    let provider = client
        .providers()
        .create(
            "OpenRouter",
            ProviderType::OpenRouter,
            std::env::var("OPENROUTER_API_KEY")?,
        )
        .await?;

    println!("BLAZING_AGENTS_PROVIDER_ID={}", provider.id);
    Ok(())
}
```

```go tab="Go"
package main

import (
	"context"
	"fmt"
	"log"
	"os"

	ba "github.com/blazingagents/golang-sdk"
)

func main() {
	ctx := context.Background()
	client, err := ba.NewClient()
	if err != nil {
		log.Fatal(err)
	}

	provider, err := client.Providers.Create(ctx, ba.CreateProviderParams{
		Name:         "OpenRouter",
		ProviderType: ba.ProviderTypeOpenRouter,
		APIKey:       ba.NewSecret(os.Getenv("OPENROUTER_API_KEY")),
	})
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("BLAZING_AGENTS_PROVIDER_ID=%s\n", provider.ID)
}
```

### Add the chat route [#add-the-chat-route]

Set `BLAZING_AGENTS_PROVIDER_ID` to the printed ID, then use the complete [TypeScript, Python, Rust, or Go chat endpoint](/getting-started/connect-your-app). It signs the user in, creates that user's own agent on their first message, and streams the reply. Every call runs as the signed-in user, so Blazing Agents keeps each user to their own agent, files, and conversations. The endpoint starts a new conversation when the request has no `sessionId`, and continues it when it does.

The endpoint gives each user their own agent because all conversations with one agent share its workspace. With one agent shared by all your users, each user's turns could read the files of every other user. See [tenancy and attribution](/platform/tenancy-and-attribution).

On the frontend, `useChat` with `BlazingAgentsChatTransport` renders the streamed reply and sends the session ID back on the next message. See [Build a chatbot](/getting-started/chatbot).

## Choose an interface [#choose-an-interface]

| Interface | Use it when |
| --- | --- |
| [TypeScript SDK](/sdk/typescript) | Your backend runs TypeScript and you want AI SDK streaming. |
| [Python SDK](/sdk/python) | Your backend runs Python, sync or async. |
| [Rust SDK](/sdk/rust) | Your backend runs Rust, async on Tokio. |
| [Go SDK](/sdk/go) | Your backend runs Go, with only the standard library. |
| [REST API](/api-reference/rest-api) | You work in another language or want direct HTTP control. |
