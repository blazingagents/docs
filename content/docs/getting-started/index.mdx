# Getting started

Go from an empty folder to an agent that answers your users inside your own app. Each step ends with something you can run, and your API key stays on your backend the whole way.

## The path [#the-shortest-path-to-a-working-agent]

<Steps>
  <Step>
    ### [Set up Blazing Agents](/getting-started/setup)

    Get an API key, install the TypeScript, Python, Rust, or Go SDK, and confirm your code can reach Blazing Agents.

  </Step>
  <Step>
    ### [Run your first agent](/getting-started/quickstart)

    Connect an OpenRouter model, create an agent, and watch its first answer stream into your terminal.

  </Step>
  <Step>
    ### [Connect Blazing Agents to your app](/getting-started/connect-your-app)

    Add a chat endpoint to your backend that signs users in, gives each one their own agent, and remembers each conversation.

  </Step>
  <Step>
    ### [Build a chatbot](/getting-started/chatbot)

    Put a React chat UI with send, stop, and regenerate on top of that endpoint.

  </Step>
  <Step>
    ### [Choose what to build next](/getting-started/next-steps)

    Give your agent files, tools, memory, or background work.

  </Step>
</Steps>

## How the pieces fit [#what-you-will-build]

Your frontend sends messages to your backend. Your backend signs the user in and calls Blazing Agents with your API key, acting as that user. Each user gets their own agent, and Blazing Agents lets each user open only their own conversations. Blazing Agents runs the agent and streams the answer back through your backend.

Your frontend never sees the API key. That matters because a key at either [access level](/platform/security-and-credentials#api-key-access-levels) can run every agent in your tenant.
