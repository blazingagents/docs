# Connect Blazing Agents to your app

Add one chat endpoint to your backend. It checks who the user is, sends their message to that user's own agent, and streams the answer back. The same endpoint returns the stored conversation and passes on messages the user sends while the agent works, which is everything the browser chat needs, whether you use the [React chat hook](/sdk/typescript/use-blazing-agents-chat) or [`BlazingAgentsChat`](/sdk/typescript/blazing-agents-chat) in another framework. Blazing Agents keeps the conversation history and lets each user open only their own conversations, so your endpoint stores just one agent ID per user.

## Before you begin [#before-you-begin]

Finish [Run your first agent](/getting-started/quickstart) and keep the same project folder and terminal. Set the provider ID it printed, and two demo tokens that stand in for your own sign-in:

```bash
export BLAZING_AGENTS_PROVIDER_ID="prv_..."
export DEMO_USER_TOKEN="demo-token"
export OTHER_USER_TOKEN="other-token"
```

The endpoint creates agents, so `BLAZING_AGENTS_API_KEY` must be the full-access key from [setup](/getting-started/setup).

<Callout type="warn" title="Keep credentials on the backend">
  Your browser or mobile app talks only to your backend. It never receives the Blazing Agents API key.
</Callout>

  <Step>
    ## Add a chat endpoint [#add-a-chat-endpoint]

    Save this as `server.ts`, `server.py`, `src/bin/server.rs`, or `server/main.go`. The `users` map stands in for your sign-in, and the map of agent IDs stands in for your database.

    ```typescript tab="TypeScript" tab-group="sdk-language" title="server.ts"
    import { serve } from "@hono/node-server";
    import { BlazingAgents, createChatRelay } from "@blazingagents/sdk";
    import { Hono } from "hono";

    const client = new BlazingAgents({
      apiKey: process.env.BLAZING_AGENTS_API_KEY!,
    });

    // Replace these with your own sign-in check and database.
    const users = new Map([
      [process.env.DEMO_USER_TOKEN!, "user-1"],
      [process.env.OTHER_USER_TOKEN!, "user-2"],
    ]);
    const agentIds = new Map<string, string>();

    async function agentFor(userId: string) {
      let agentId = agentIds.get(userId);
      if (!agentId) {
        const agent = await client.forUser(userId).agents.create({
          name: "Chat agent",
          providerId: process.env.BLAZING_AGENTS_PROVIDER_ID!,
          model: "openai/gpt-6-luna",
        });
        agentId = agent.id;
        agentIds.set(userId, agentId);
      }
      return agentId;
    }

    const relayChat = createChatRelay({
      client,
      async resolveContext(request) {
        const token = request.headers.get("authorization")?.replace("Bearer ", "");
        const userId = token ? users.get(token) : undefined;
        return userId ? { agentId: await agentFor(userId), userId } : null;
      },
    });

    const app = new Hono();
    app.post("/api/chat", (c) => relayChat(c.req.raw));
    serve({ fetch: app.fetch, port: 8787 });
    ```

    ```python tab="Python" title="server.py"
    import os

    from blazing_agents import AsyncBlazingAgents, AsyncChatRelay, RelayContext
    from fastapi import FastAPI, Request
    from fastapi.responses import StreamingResponse

    client = AsyncBlazingAgents()
    app = FastAPI()

    # Replace these with your own sign-in check and database.
    users = {
        os.environ["DEMO_USER_TOKEN"]: "user-1",
        os.environ["OTHER_USER_TOKEN"]: "user-2",
    }
    agent_ids: dict[str, str] = {}


    async def agent_for(user_id: str) -> str:
        if user_id not in agent_ids:
            agent = await client.for_user(user_id).agents.create(
                name="Chat agent",
                provider_id=os.environ["BLAZING_AGENTS_PROVIDER_ID"],
                model="openai/gpt-6-luna",
            )
            agent_ids[user_id] = agent.id
        return agent_ids[user_id]


    async def resolve_context(request: Request) -> RelayContext | None:
        token = request.headers.get("authorization", "").removeprefix("Bearer ")
        user_id = users.get(token)
        if user_id is None:
            return None
        return RelayContext(agent_id=await agent_for(user_id), user_id=user_id)


    relay = AsyncChatRelay(client=client, resolve_context=resolve_context)


    @app.post("/api/chat")
    async def chat(request: Request) -> StreamingResponse:
        answer = await relay.handle(request, await request.body())
        return StreamingResponse(answer, status_code=answer.status_code, headers=answer.headers)
    ```

    ```rust tab="Rust" title="src/bin/server.rs"
    use axum::Router;
    use axum::body::Bytes;
    use axum::extract::{Request, State};
    use axum::response::Response;
    use axum::routing::post;
    use blazing_agents::Client;
    use blazing_agents::ids::AgentId;
    use blazing_agents::relay::{ChatRelay, RelayBody, RelayContext};
    use std::collections::HashMap;
    use std::error::Error;
    use std::sync::{Arc, Mutex};
    use tokio::net::TcpListener;

    struct App {
        client: Client,
        provider_id: String,
        // Replace these with your own sign-in check and database.
        users: HashMap<String, String>,
        agent_ids: Mutex<HashMap<String, AgentId>>,
    }

    impl App {
        async fn resolve_context(
            &self,
            request: axum::http::Request<Bytes>,
        ) -> Result<Option<RelayContext>, Box<dyn Error + Send + Sync>> {
            let token = request
                .headers()
                .get("authorization")
                .and_then(|value| value.to_str().ok())
                .map(|value| value.trim_start_matches("Bearer "))
                .unwrap_or_default();
            let Some(user_id) = self.users.get(token).cloned() else {
                return Ok(None);
            };
            let stored = self.agent_ids.lock().unwrap().get(&user_id).cloned();
            let agent_id = match stored {
                Some(agent_id) => agent_id,
                None => {
                    let agent = self
                        .client
                        .for_user(&user_id)?
                        .agents()
                        .create("Chat agent")
                        .model(&self.provider_id, "openai/gpt-6-luna")
                        .await?;
                    self.agent_ids.lock().unwrap().insert(user_id.clone(), agent.id.clone());
                    agent.id
                }
            };
            Ok(Some(RelayContext::new(agent_id, user_id)))
        }
    }

    async fn chat(State(relay): State<ChatRelay>, request: Request) -> Response<RelayBody> {
        relay.handle(request).await
    }

    #[tokio::main]
    async fn main() -> Result<(), Box<dyn Error>> {
        let app = Arc::new(App {
            client: Client::from_env()?,
            provider_id: std::env::var("BLAZING_AGENTS_PROVIDER_ID")?,
            users: HashMap::from([
                (std::env::var("DEMO_USER_TOKEN")?, "user-1".to_string()),
                (std::env::var("OTHER_USER_TOKEN")?, "user-2".to_string()),
            ]),
            agent_ids: Mutex::new(HashMap::new()),
        });
        let relay = ChatRelay::new(app.client.clone(), move |request| {
            let app = app.clone();
            async move { app.resolve_context(request).await }
        });
        let router = Router::new()
            .route("/api/chat", post(chat))
            .with_state(relay);
        let listener = TcpListener::bind("0.0.0.0:8787").await?;
        axum::serve(listener, router).await?;
        Ok(())
    }
    ```

    ```go tab="Go" title="server/main.go"
    package main

    import (
    	"context"
    	"log"
    	"net/http"
    	"os"
    	"strings"
    	"sync"

    	ba "github.com/blazingagents/golang-sdk"
    )

    type app struct {
    	client     *ba.Client
    	providerID ba.ProviderID
    	// Replace these with your own sign-in check and database.
    	users    map[string]string
    	mu       sync.Mutex
    	agentIDs map[string]ba.AgentID
    }

    func (a *app) agentFor(ctx context.Context, userID string) (ba.AgentID, error) {
    	a.mu.Lock()
    	defer a.mu.Unlock()
    	if agentID, ok := a.agentIDs[userID]; ok {
    		return agentID, nil
    	}
    	user, err := a.client.ForUser(userID)
    	if err != nil {
    		return "", err
    	}
    	agent, err := user.Agents.Create(ctx, ba.CreateAgentParams{
    		Name:       "Chat agent",
    		ProviderID: ba.Value(a.providerID),
    		Model:      ba.Value("openai/gpt-6-luna"),
    	})
    	if err != nil {
    		return "", err
    	}
    	a.agentIDs[userID] = agent.ID
    	return agent.ID, nil
    }

    func (a *app) resolveContext(r *http.Request) (*ba.RelayContext, error) {
    	token := strings.TrimPrefix(r.Header.Get("Authorization"), "Bearer ")
    	userID, ok := a.users[token]
    	if !ok {
    		return nil, nil
    	}
    	agentID, err := a.agentFor(r.Context(), userID)
    	if err != nil {
    		return nil, err
    	}
    	return &ba.RelayContext{AgentID: agentID, UserID: userID}, nil
    }

    func main() {
    	client, err := ba.NewClient()
    	if err != nil {
    		log.Fatal(err)
    	}
    	a := &app{
    		client:     client,
    		providerID: ba.ProviderID(os.Getenv("BLAZING_AGENTS_PROVIDER_ID")),
    		users: map[string]string{
    			os.Getenv("DEMO_USER_TOKEN"):  "user-1",
    			os.Getenv("OTHER_USER_TOKEN"): "user-2",
    		},
    		agentIDs: map[string]ba.AgentID{},
    	}
    	http.Handle("POST /api/chat", ba.NewChatRelay(client, a.resolveContext))
    	log.Fatal(http.ListenAndServe(":8787", nil))
    }
    ```

    Start it with `node server.ts`, `uvicorn server:app --port 8787`, `cargo run --bin server`, or `go run ./server`.

    ## Verify the integration [#verify-the-integration]

    In a second terminal, export `DEMO_USER_TOKEN` and `OTHER_USER_TOKEN` again and ask the agent to remember something:

    ```bash
    curl -i -N http://localhost:8787/api/chat \
      -H "authorization: Bearer $DEMO_USER_TOKEN" \
      -H "content-type: application/json" \
      -d '{"op":"chat","message":{"id":"m1","role":"user","parts":[{"type":"text","text":"Remember the word cobalt."}]}}'
    ```

    The answer streams in as `data: {...}` lines. Among the response headers is a `location` header that ends in the new `ss_...` session ID. Send it back with a follow-up question:

    ```bash
    curl -N http://localhost:8787/api/chat \
      -H "authorization: Bearer $DEMO_USER_TOKEN" \
      -H "content-type: application/json" \
      -d '{"op":"chat","sessionId":"ss_...","message":{"id":"m2","role":"user","parts":[{"type":"text","text":"Which word did I ask you to remember?"}]}}'
    ```

    The agent answers "cobalt", because Blazing Agents kept the first exchange. Read the stored conversation the way the browser does after a reload:

    ```bash
    curl http://localhost:8787/api/chat \
      -H "authorization: Bearer $DEMO_USER_TOKEN" \
      -H "content-type: application/json" \
      -d '{"op":"history","sessionId":"ss_..."}'
    ```

    You get `{"data":[...],"nextCursor":null}`, with both questions and both answers in `data`. Now send the same session ID as the other user:

    ```bash
    curl -i http://localhost:8787/api/chat \
      -H "authorization: Bearer $OTHER_USER_TOKEN" \
      -H "content-type: application/json" \
      -d '{"op":"chat","sessionId":"ss_...","message":{"id":"m3","role":"user","parts":[{"type":"text","text":"Which word did I ask you to remember?"}]}}'
    ```

    You get `404`, because the session belongs to the first user. Leave out the `authorization` header and you get `401`.

## What happened [#persist-and-resume-the-session]

The first request from each user finds no stored agent ID, so the endpoint creates an agent with a client scoped to that user: `client.forUser(userId)` in TypeScript, `client.for_user(user_id)` in Python and Rust, and `client.ForUser(userID)` in Go. The new agent and the workspace it comes with belong to that user. The endpoint then sends the message through the same scoped client.

A request without a `sessionId` starts a new session that belongs to the user, and Blazing Agents returns its ID before the answer finishes streaming. A later request with that `sessionId` continues the conversation, and the agent sees everything said so far. Your frontend sends only the newest message each time. The scoped client reaches only that user's agents, sessions, and workspaces, so a session ID from anyone else returns `404` and you keep no table of who owns which conversation.

Each user gets their own agent because every turn of an agent runs in that agent's one workspace. If all your users chatted with one shared agent, their turns would share one workspace, and one user's files would be readable from another user's turns. See [tenancy and attribution](/platform/tenancy-and-attribution) for how agents, workspaces, and sessions belong to your users.

The request body's `op` says what the browser needs. `chat` runs a turn, `history` returns one page of the stored conversation, and `steer` sends a message into the turn that is running. The SDK's chat relay answers all three: `createChatRelay()` in TypeScript, `AsyncChatRelay` in Python, `ChatRelay` in Rust, and `ba.NewChatRelay()` in Go. Your code only signs the request in and returns the user and their agent, or nothing to answer `401`. The relay scopes each request to that user, and a user who presses Stop or closes the tab stops the turn. It returns API errors as `{"error":{"code","message"}}` with the API's status, so the browser can tell a deleted session from a turn that cannot take a steer. The [browser chat relay](/api-reference/protocols/browser-relay) describes every request, for a backend in another language.

The agents this endpoint creates use the default approval policy, which runs every tool without asking, so no turn here waits for a person. If you turn on [human approval](/agents/tools/tool-approvals#human-approval-flow), the relay already forwards the user's answers and streams the rest of the turn.

## Production notes [#production-notes]

- Replace the demo tokens with your real sign-in, and store each user's agent ID with the user in your database.
- Create each user's agent once, for example when the user signs up. [Creating agents is rate-limited](/api-reference/protocols/service-limits#tenant-resource-creation-rate) per tenant, so do not create one on every request.
- Use a full-access key for a backend that creates agents. A backend that only runs agents that already exist can use a read-only key. See [API key access levels](/platform/security-and-credentials#api-key-access-levels).
- Keep the session ID even when the first turn fails or the user stops it. The conversation exists; it is empty until a turn succeeds.
- If the browser calls the endpoint from another origin, allow the `authorization` and `content-type` request headers in your CORS settings and expose the `Location` response header, so the browser can read the new session ID.
- Streams must reach the browser unbuffered. The relay already sets `Cache-Control: no-cache` and `X-Accel-Buffering: no`; make sure every proxy in front of your backend passes the stream through as it arrives.
