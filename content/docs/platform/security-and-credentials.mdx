# Security and credentials

Keep every secret on your server and let Blazing Agents hold the rest. Your API key stays in your backend, model keys and MCP credentials are stored for you and never returned, and the agent's workspace never sees any of them.

## Keep the API key on your backend [#keep-the-api-key-on-your-backend]

A Blazing Agents API key acts for your whole account. Only your backend should hold it. The API is backend-only, so there is no key that is safe to ship in a browser or mobile app.

<Callout type="warn" title="Keep credentials on the backend">
  Never put a Blazing Agents API key or any other service credential in a browser bundle, mobile binary, public-prefixed environment variable, URL, or client-visible error.
</Callout>

The key identifies your account, not your end user. Your backend signs in the user and derives a [user-scoped client](/sdk/typescript/client#for-user) from that verified identity. Blazing Agents then checks ownership of user-owned resources. A `userId` in a request body is a reporting label, not a permission. See [tenancy and attribution](/platform/tenancy-and-attribution).

## Check your key [#check-your-key]

Load the key from your server environment and read your account settings:

```typescript tab="TypeScript"
import { BlazingAgents } from "@blazingagents/sdk";

const client = new BlazingAgents({
  apiKey: process.env.BLAZING_AGENTS_API_KEY!,
});
const settings = await client.tenant.get();
console.log(settings.name);
```

```python tab="Python"
from blazing_agents import BlazingAgents

client = BlazingAgents()
settings = client.tenant.get()
print(settings.name)
```

```rust tab="Rust"
use blazing_agents::Client;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = Client::from_env()?;
    let settings = client.tenant().get().await?;
    println!("{}", settings.name);
    Ok(())
}
```

```go tab="Go"
package main

import (
	"context"
	"fmt"
	"log"

	ba "github.com/blazingagents/golang-sdk"
)

func main() {
	ctx := context.Background()
	client, err := ba.NewClient()
	if err != nil {
		log.Fatal(err)
	}
	settings, err := client.Tenant.Get(ctx)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(settings.Name)
}
```

The Python, Rust, and Go clients read `BLAZING_AGENTS_API_KEY` from the environment. If the key is valid, you see your account name. A missing, revoked, or expired key returns [`unauthorized`](/api-reference/protocols/errors#unauthorized).

## Dashboard API-key management [#dashboard-api-key-management]

Create, list, and revoke API keys in the dashboard at [`www.blazingagents.com/app/keys`](https://www.blazingagents.com/app/keys). You must be signed in to the dashboard. An API key cannot create, list, rotate, or revoke keys, including itself, and the SDKs have no key-management methods.

- **Choose an access level.** There is no default; see [access levels](#api-key-access-levels).
- **Name each key** for one workload or environment, such as `Production API` or `Staging worker`.
- **Pick an expiration** when the workload has a known lifetime, or choose **No expiration** for a long-lived backend key.
- **Copy the key right away.** The full `ba_read_...` or `ba_full_...` value appears once. Afterwards the dashboard shows only a short fragment, and Blazing Agents cannot show the key again. If you lose it, create a new one.

To rotate a key, create a new one, deploy it to every backend instance, confirm the workload runs, then revoke the old key. Revocation takes effect immediately, and an expired key stops working the same way.

### Access levels [#api-key-access-levels]

Every key has one of two access levels. The level is part of the key: you cannot change it later. To change it, create a key with the level you want and revoke the old one, the same as rotation.

| Level | Key starts with | What it can do | Use it for |
| --- | --- | --- | --- |
| **Full** | `ba_full_` | Everything a read-only key can do, plus creating, changing, and deleting your setup. | The backend or tool that manages your agents and their configuration. |
| **Read-only** | `ba_read_` | Read every resource the API exposes and run your agents: start chats, run tasks, and call generation, which spends credit. It cannot create, change, or delete agents, skills, prompts, workspaces, tasks, providers, or other settings. | A production backend that only runs agents, dashboards, reporting, and coding agents that should not change your setup. |

A read-only key that tries to change your setup gets [`insufficient_scope`](/api-reference/protocols/errors#insufficient_scope) (403). The call is refused before it runs, so nothing changes and nothing is charged. A read-only key can chat with the Admin Agent, but that chat offers only the Admin Agent's read actions, and any change the model asks for fails as a tool error. A read-only key also cannot approve a pending change or steer a turn that a full key started. No key, at either level, can manage API keys.

<Callout type="warn" title="Read-only is not harmless">
  Read-only means it cannot change your setup, not that it has no effect. A read-only key spends credit, creates sessions, and lets your agents use their own tools, such as workspaces, MCP connections, and memories, during a turn. It also reads session messages, which contain your end users' text, and can create artifact download URLs, which give file contents to anyone who holds them. Protect it like a full key.
</Callout>

## Provider keys [#provider-keys]

When you [create a provider](/agents/providers-and-models), you send its model API key once. Blazing Agents stores it and never returns it. Responses show only the last four characters. The key is never written into sessions, tasks, or the agent's workspace.

You can rename a provider, but you cannot change its key, type, or base URL. To change any of those, create a new provider, move your agents to it, then delete the old one.

A Vercel AI Gateway provider stores only your Gateway API key. Vendor keys, routing, fallbacks, and billing stay configured in Vercel.

## MCP credentials and outbound calls [#mcp-credentials-and-outbound-calls]

[MCP connections](/agents/tools/mcp-tools) support no authentication, a bearer token, OAuth authorization code, and OAuth client credentials. Blazing Agents stores the credentials, refreshes OAuth tokens, and adds them to each request to the remote server. The agent never sees them as tool arguments.

Error messages from MCP setup and tool calls have credentials removed. Tool definitions or results that contain a stored credential are rejected. Outbound MCP requests are checked for allowed schemes and addresses, limited in redirects, time, and response size, and sensitive headers are dropped on cross-origin redirects.

## Workspace isolation [#workspace-isolation]

Each agent's [workspace](/agents/workspaces) sees only its own files, under `/workspace`. Your API key, provider keys, and MCP credentials never appear there as files or environment variables, so a command the agent runs cannot read them.

The workspace network policy controls outbound traffic: open internet access, an allowlist of hosts, or no network at all. Published [artifacts](/agents/artifacts) are stored separately from the workspace and stay available after workspace files change.

## Delete your account [#delete-your-account]

Delete your account from **Settings → Delete tenant** in the [dashboard](https://www.blazingagents.com/app).

1. Cancel your subscription first, in **Settings → Subscription**. Your plan stays active until your next billing date, and the current period is not refunded. Until you cancel, a deletion request is refused with [`subscription_not_cancelled`](/api-reference/protocols/errors#subscription_not_cancelled).
2. Request the deletion. It happens 24 hours later. New turns and task runs stop at once, and work that is already running finishes. Everything else keeps working, so you can export what you need.
3. To keep the account, cancel the deletion before its scheduled time. Your subscription stays cancelled; resume it in **Settings → Subscription** if you want to keep your plan.

At the scheduled time, Blazing Agents deletes your workspaces, agents, sessions, files, credentials, and sign-in, and closes your billing account. A Telegram bot that still delivers to Blazing Agents has its webhook removed. Blazing Agents deletes its copy of your MCP OAuth tokens but does not revoke them at the MCP server; revoke them there if you want them gone sooner than they expire.

Some copies outlive the deletion for a limited time:

- Saved copies of [Plus workspaces](/agents/workspaces#snapshot-resume) stay with our infrastructure provider and are erased within about 30 days.
- Records of finished background jobs and of billing notifications, which can include your account ID and billing email, are deleted 90 days after they finish.

## Safe logging [#safe-logging]

- Load credentials from a secret manager or server environment.
- Never log `Authorization` headers, API keys, provider keys, MCP or OAuth credentials, or artifact download URLs.
- Log request IDs and resource IDs for support. Leave out prompts, message content, and tool input and output.
- Return sanitized errors to your users. Your own logs are not redacted for you.
- Treat key fragments as display hints, not as credentials.
