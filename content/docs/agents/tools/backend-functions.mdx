# Backend functions

Attach your backend functions to a chat request so the agent can use your application code. The function runs in your backend, where it can use your database connections and credentials. Blazing Agents receives its description, input schema, and result.

## Attach a function [#attach-a-function]

Use an agent with a provider and model. Keep its `approvalInChat.default` at `"full"`, the default, so the function runs without a manual decision. Set `BLAZING_AGENTS_API_KEY` and `BLAZING_AGENTS_AGENT_ID` in your backend environment.

This example gives the agent a shipping quote function. Replace the sample rates with your application's pricing service.

```typescript tab="TypeScript"
import { BlazingAgents, defineFunction } from "@blazingagents/sdk";
import { z } from "zod";

const client = new BlazingAgents({
	apiKey: process.env.BLAZING_AGENTS_API_KEY!,
});

const functions = {
	shippingQuote: defineFunction({
		description: "Get the shipping price for a destination country.",
		inputSchema: z.object({ country: z.enum(["GB", "US"]) }),
		execute: ({ country }) => ({
			currency: "GBP",
			amountMinor: country === "GB" ? 499 : 1499,
		}),
	}),
};

const result = await client.chat({
	agentId: process.env.BLAZING_AGENTS_AGENT_ID!,
	message: {
		id: crypto.randomUUID(),
		role: "user",
		parts: [{ type: "text", text: "How much is shipping to the US?" }],
	},
	functions,
});

for await (const chunk of result.toStream()) {
	process.stdout.write(chunk);
}
```

```python tab="Python"
import os
import sys
from typing import Literal

from blazing_agents import BlazingAgents, FunctionContext, define_function
from pydantic import BaseModel


class ShippingInput(BaseModel):
	country: Literal["GB", "US"]


def shipping_quote(value: ShippingInput, context: FunctionContext) -> dict:
	return {
		"currency": "GBP",
		"amountMinor": 499 if value.country == "GB" else 1499,
	}


functions = {
	"shippingQuote": define_function(
		description="Get the shipping price for a destination country.",
		input_schema=ShippingInput,
		execute=shipping_quote,
	),
}

with BlazingAgents() as client:
	with client.chat(
		agent_id=os.environ["BLAZING_AGENTS_AGENT_ID"],
		message={
			"id": "shipping-question",
			"role": "user",
			"parts": [{"type": "text", "text": "How much is shipping to the US?"}],
		},
		functions=functions,
	) as stream:
		for chunk in stream:
			sys.stdout.buffer.write(chunk)
```

The SDK validates the call's arguments, runs your handler, and sends its JSON result to the agent. Keep reading or relaying the stream until the answer finishes. In a TypeScript HTTP route, return `result.toResponse()` to stream the answer to your browser.

Supply `functions` again on each new chat request. The functions belong to that request and are not saved in the agent's configuration or anywhere else. Tasks, including scheduled tasks, and stateless generation cannot use backend functions. Use [MCP tools](/agents/tools/mcp-tools) for those workloads.

## Use application identity [#use-application-identity]

Build handlers after you authenticate the request. Capture the signed-in user's identity in the handler and use it in database queries. A model-provided user ID is not proof that the caller may access another user's data.

With TypeScript, use `client.forUser(userId)` to scope the chat session to the authenticated user. Python applications must authorize session access in their backend. Keep your API key and the function handlers on the server.

## Resume after approval [#resume-after-approval]

Backend functions follow the agent's `approvalInChat.default` policy. Per-tool overrides apply to built-in and MCP tools. See [tool approvals](/agents/tools/tool-approvals) to configure the policy and collect a reviewer's decisions.

When any call waits for a person, nothing runs until your backend sends the whole round's decisions. Pass the same `functions` on that call so the resumed turn can use them, whatever tool caused the pause:

```typescript tab="TypeScript"
const continued = await client.continueChat({ agentId, sessionId, decisions, functions });
return continued.toResponse();
```

```python tab="Python"
with client.continue_chat(
	agent_id=agent_id,
	session_id=session_id,
	decisions=decisions,
	functions=functions,
) as stream:
	for chunk in stream:
		sys.stdout.buffer.write(chunk)
```

The function descriptions and schemas go out again with this request, so keep the handlers compatible with what the model saw. A missing handler or invalid input becomes a tool error.

## Handle cancellation and retries [#handle-cancellation-and-retries]

Each handler receives a context. TypeScript provides `idempotencyKey` and `signal`. Python provides `idempotency_key`, `deadline_at`, and a `cancelled` event.

Each function call must return within 60 seconds of the agent making it. After that, the agent gets a tool error that says the outcome is unknown or the call did not run, even if your handler finishes later.

Use the idempotency key when you call a service that supports duplicate prevention. It identifies one function execution. If a user sends the same request again, the new call has a new key, so business operations such as payments still need your own stable transaction ID.

Cancellation is cooperative. Pass the TypeScript signal to operations that accept it, and check Python's cancellation event in synchronous handlers. Python async handlers are cancelled when their deadline expires or their stream closes. Cancellation cannot undo a side effect that already happened.

Before your handler runs, the SDK asks Blazing Agents for the call, and afterward it sends back the result. It retries either request after a temporary network failure without running your handler again. If the deadline has passed or another reader already took the call, the SDK skips your handler and the stream carries on. Other request failures and malformed function events raise an error while you read the stream. If the connection fails after a side effect, its outcome may be unknown. Check your application's records before repeating it.

Return plain JSON values. Convert dates or model instances explicitly before you return them. Handler exceptions, invalid arguments, and invalid results become sanitized tool errors. Exception details are not sent to the agent.
