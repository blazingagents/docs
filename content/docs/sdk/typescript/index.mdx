# TypeScript SDK

`@blazingagents/sdk` gives your Node.js backend a typed client for every Blazing Agents operation. You configure agents and their resources through methods like `client.agents.create()`, and you run turns with `client.chat()`, which streams in the format the AI SDK `useChat` hook reads.

<Callout type="warn" title="Server-side only">
  Your API key can reach every resource in your tenant. Keep it in backend code
  and never send it to a browser or mobile app.
</Callout>

## Install [#install]

The SDK needs Node.js 24 or later and the `ai` package version 7 alongside it.

```bash
npm install @blazingagents/sdk ai
```

## Initialize the client [#initialize-the-client]

```typescript
import { BlazingAgents } from "@blazingagents/sdk";

export const client = new BlazingAgents({
  apiKey: process.env.BLAZING_AGENTS_API_KEY!,
});
```

The client talks to `https://api.blazingagents.com`, so you only pass your key. Creating it makes no network request. See [Client](/sdk/typescript/client) for request correlation, a custom `fetch`, and response logging.

## Common workflow [#common-workflow]

Connect a model provider, create an agent, and run a first turn:

```typescript
import { BlazingAgents } from "@blazingagents/sdk";

const client = new BlazingAgents({
  apiKey: process.env.BLAZING_AGENTS_API_KEY!,
});

const provider = await client.providers.create({
  name: "OpenRouter",
  providerType: "openrouter",
  baseUrl: null,
  apiKey: process.env.OPENROUTER_API_KEY!,
});

const agent = await client.agents.create({
  name: "Support agent",
  providerId: provider.id,
  model: "openai/gpt-6-luna",
});

const result = await client.chat({
  agentId: agent.id,
  message: {
    id: crypto.randomUUID(),
    role: "user",
    parts: [{ type: "text", text: "How can I reset my password?" }],
  },
});

console.log(`Session: ${await result.sessionId}`);
console.log(await result.toResponse().text());
```

The last line prints the raw stream events, including the answer in `text-delta` events. Save the session ID and pass it as `sessionId` on the next `chat()` call to continue the conversation. In a web app, return `result.toResponse()` from your route instead of reading it. For one-off text or JSON without a session, use [`completion()`](/sdk/typescript/client#completion) or [`object()`](/sdk/typescript/client#object).

## Client objects [#client-objects]

| Object | What it manages |
| --- | --- |
| [`BlazingAgents`](/sdk/typescript/client) | Client options plus `chat()`, `completion()`, and `object()` |
| [`agents`](/sdk/typescript/agents) | Agents, their versions, avatars, and MCP settings |
| [`workspaces`](/sdk/typescript/workspaces) | Workspaces and their network rules |
| [`agent({ agentId }).skills`](/sdk/typescript/skills) | One agent's skills and skill files |
| [`sessions`](/sdk/typescript/sessions) | Conversation history and tool approvals |
| [`providers`](/sdk/typescript/providers) | Model provider keys and model lists |
| [`mcpConnections`](/sdk/typescript/mcp-connections) | Remote MCP servers and their sign-in |
| [`memories`](/sdk/typescript/memories) | Notes an agent keeps across sessions |
| [`artifacts`](/sdk/typescript/artifacts) | Files agents publish, and their downloads |
| [`tasks`](/sdk/typescript/tasks) | Background tasks, runs, and schedules |
| [`prompts`](/sdk/typescript/prompts) | Reusable prompt templates |
| [`usage`](/sdk/typescript/usage) | Token and request usage |
| [`tenant`](/sdk/typescript/tenant) | Tenant name and settings |
| [`chatConnections`](/sdk/typescript/chat-integrations) | Slack and Telegram bots |
| [`chatDeliveries`](/sdk/typescript/chat-integrations#list-deliveries) | Failed and ambiguous deliveries across your Slack and Telegram bots |
| `merchantConnection`, `merchantBindings`, `merchantUsageEvents` | [Billing your users](/platform/monetization) |

Every method takes one input object. Put IDs, fields, and an optional `abortSignal` side by side in it. See [Cancellation](/sdk/typescript/client#cancellation).

## Errors [#errors]

Every failed request throws `BlazingAgentsError`. Branch on its `code`, and log its `requestId` if you contact support. See [Client errors](/sdk/typescript/client#errors) for the full list of fields and SDK codes.
