# SDK

Manage agents, run turns, and read results from your backend code with a typed client. Each SDK covers the full API, checks responses for you, and reports a typed error when a request fails.

```typescript tab="TypeScript" tab-group="sdk-language"
import { BlazingAgents } from "@blazingagents/sdk";

const client = new BlazingAgents({
  apiKey: process.env.BLAZING_AGENTS_API_KEY!,
});

const { data: agents } = await client.agents.list();
```

```python tab="Python"
from blazing_agents import BlazingAgents

client = BlazingAgents()

agents = client.agents.list().data
```

```rust tab="Rust"
use blazing_agents::Client;

let client = Client::from_env()?;

let agents = client.agents().list().await?.data;
```

```go tab="Go"
client, err := ba.NewClient()
if err != nil {
	return err
}

page, err := client.Agents.List(ctx, ba.ListAgentsParams{})
if err != nil {
	return err
}
agents := page.Data
fmt.Println(len(agents))
return nil
```

Keep your API key on the server, and never ship it to a browser or mobile app. Use a full key (`ba_full_…`) for the code that creates and changes agents, providers, and other setup. A read-only key (`ba_read_…`) can read your setup and run your agents but cannot change your setup, which suits a backend that only serves your users. See [access levels](/platform/security-and-credentials#api-key-access-levels).

Either key reaches every resource in your tenant. In a route that serves one signed-in user, call the SDK through a user-scoped client, so it reads and runs only that user's records: [`forUser()`](/sdk/typescript/client#for-user) in TypeScript, [`for_user()`](/sdk/python/client#for-user) in Python and [Rust](/sdk/rust/client#for-user), and [`ForUser()`](/sdk/go/client#for-user) in Go.
