# CLI

`ba` puts your agents in your terminal. Chat with an agent while you tune its instructions, run it from a script or CI job, or ask the built-in assistant to manage your tenant for you. Everything runs on Blazing Agents, so the CLI never runs tools on your machine.

## Install the CLI [#install-the-cli]

You need Node.js 24 or later.

```bash
npm install --global @blazingagents/cli@0.1.0
ba --version
```

You see `0.1.0`. Run `ba --login` next to connect the CLI to your account (see [setup and authentication](/cli/setup-and-authentication)), then chat with the agent from the quickstart:

```bash
ba --login
ba chat "Quickstart agent"
```

A chat window opens in your terminal. Type a message and the answer streams in.

## Choose a command [#choose-a-command]

| Command | What it does | Use it for |
| --- | --- | --- |
| [`ba chat <agent>`](/cli/chat) | Opens an interactive chat with one of your agents | Trying out and tuning an agent |
| [`ba run <agent>`](/cli/run) | Runs one turn with no interaction and prints the answer | Scripts, pipes, and [CI jobs](/cli/scripting-and-ci) |
| [`ba assist`](/cli/assist) | Opens a chat with the built-in assistant that manages your tenant | Creating agents, prompts, and tasks, or checking usage, in plain language |

Run `ba --help` or `ba <command> --help` for every flag. Help never needs a network connection or a stored key.

## Choose an agent [#operational-boundaries]

`ba chat` and `ba run` take an agent ID (`ag_...`) or the agent's full name. An exact name wins. Otherwise the CLI accepts a single match that ignores case, and lists the candidates with their IDs if there are several. Partial names never match.

The agent needs a provider and model before it can answer. The quickstart agent already has both.

## Point the CLI at another API [#configure-the-api-origin]

The CLI talks to `https://api.blazingagents.com`. To use a different address, pass `--base-url`, set `BLAZING_AGENTS_BASE_URL`, or put a `baseUrl` line in a config file. They win in that order.

```yaml title="config.yaml"
baseUrl: https://api.blazingagents.com
```

The file lives at `~/.config/blazing-agents/config.yaml` on macOS and Linux (or under `$XDG_CONFIG_HOME` if set), and at `%APPDATA%\blazing-agents\config.yaml` on Windows. It holds only `baseUrl`, never a key. The CLI never writes to it.
